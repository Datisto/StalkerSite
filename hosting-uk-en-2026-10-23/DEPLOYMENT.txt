ETERNAL ZONE — ОНОВЛЕННЯ UA / EN
Пакет від 23.10.2026. Для наявного працюючого сайту.

ЩО ДОДАНО
Перемикач UA / EN; англійські поля правил, підпунктів і категорій, тестових питань,
FAQ, назв відео та підписів облич. Українська — основна; за відсутності перекладу
показується український текст. Вибір облич персонажів зберігає початкові ідентифікатори.
Статичні тексти інтерфейсу перекладено: головна, Discord, форми, діалоги,
підказки, статуси, вибір характеристик персонажа та адмінка. Значення вибору,
які зберігаються в базі, не змінюються при перемиканні мови.
Англійські тексти вмісту з бази додаються вручну в адмінці. Власні біографії,
відповіді гравців, імена та коментарі цей пакет автоматично не перекладає.

ВМІСТ ПАКЕТА
01_database.sql — загальний SQL саме для MariaDB 11.8.x і бази dayzstal_eternalzone, усі 11 полів.
SQL_SAFETY_REPORT.json — результати перевірки на локальній MariaDB 11.8.9 зі штучними записами.
02_backend.zip — 9 змінених серверних файлів; корінь архіву містить папку src/.
03_frontend.zip — готовий вміст dist/: index.html, assets/ та публічні ресурси.
UPLOAD_MANIFEST.json — повний список файлів, джерела та SHA-256.
У пакеті немає .env, паролів, node_modules та конфігурації вебсервера.

ПОРЯДОК ОНОВЛЕННЯ ДЛЯ ОБОХ ВАРІАНТІВ
1. Збережіть повний експорт СТРУКТУРИ ТА ДАНИХ робочої бази й копії файлів,
   які будете замінювати. Надісланий дамп лише структури не містить резервної копії записів.
2. Відкрийте окреме з’єднання HeidiSQL або phpMyAdmin до поточного хостингу.
   Виберіть dayzstal_eternalzone та імпортуйте ВЕСЬ новий 01_database.sql одним запуском.
   У HeidiSQL використовуйте виконання SQL-файлу; у phpMyAdmin — вкладку «Імпорт».
   Файл містить DELIMITER і один BEGIN NOT ATOMIC: не запускайте його частинами
   та не використовуйте імпортер, який не підтримує DELIMITER.
   Потрібні MariaDB 11.8.x, autocommit=1 та відсутність відкритої транзакції.
   Файл сам вибирає dayzstal_eternalzone, а всі ALTER адресовано саме цій базі.
   Не завантажуйте SQL у public_html. schema.sql та старий add_english_content.sql
   для цього оновлення запускати не потрібно.
   Перед першою зміною перевіряються 8 таблиць, рушій, кодування, типи й NULL
   60 початкових полів та сумісність вже наявних англійських полів.
   Скрипт додає відсутні поля в кінець таблиць; наявні записи, ключі й переклади не змінює.
   Додавання дозволено тільки з ALGORITHM=INSTANT та LOCK=NONE, без перебудови таблиці.
   Очікування metadata lock обмежене 5 секундами; попередній таймаут з’єднання
   відновлюється після успіху або помилки. Повна тривалість імпорту не обмежена 5 секундами.
   Успіх: migration_status=OK, columns_added + columns_already_present = 11,
   далі — 11 рядків із визначеннями полів.
   При помилці решта захисного блоку не виконується. Раніше успішні DDL-зміни
   залишаються застосованими: загального відкату через ROLLBACK немає.
   Після усунення причини той самий файл можна виконати повторно — сумісні поля пропускаються.
   При помилці INSTANT або перевірки структури не прибирайте захисні умови навмання;
   не переходьте до оновлення backend, поки весь SQL не завершиться з OK.
3. Завантажте backend за відповідним варіантом нижче, замінивши наявні 9 файлів.
4. Перезапустіть поточну Node.js-програму її штатною кнопкою Restart / «Перезапуск».
   Не створюйте другу програму. .env, параметри запуску та маршрути /api збережіть.
   Залежності не змінювалися: для цього оновлення npm install не потрібен.
5. Завантажте frontend за відповідним варіантом нижче. Спершу assets/ і решту
   ресурсів, index.html — останнім, щоб він посилався на вже завантажені файли.
   Старі файли assets/ можна залишити, якщо вони потрібні відкритим сторінкам.

ВАРІАНТ A: cPanel, public_html + ОКРЕМИЙ BACKEND
Frontend: розпакуйте ВМІСТ 03_frontend.zip у корінь сайту домену.
Для основного домену це часто public_html; для додаткового домену дивіться його
Document Root у cPanel → Domains. Не створюйте вкладену папку dist/ у корені сайту.
У підсумку файл має бути <Document Root>/index.html, а ресурси — <Document Root>/assets/.
Збережіть наявний .htaccess: архів не містить заміни для нього.

Backend: у cPanel → Setup Node.js App / Application Manager знайдіть Application Root
і поточний startup file. Потрібна вже наявна папка src/, що містить routes/faq.js.
Розпакуйте ВМІСТ 02_backend.zip поруч із цією папкою src/, щоб файли замінили
саме існуючі src/routes/*.js та додали src/utils/content-translations.js.
Якщо startup file = src/index.js, місце розпакування зазвичай збігається з Application Root.
Якщо програма запускає server/src/index.js з кореня проєкту, розпаковуйте backend
у наявну папку server/, а не поруч із нею. Не завантажуйте backend у public_html.
Наявне направлення /api на Node.js має залишитися чинним. Нові маршрути
/faq/manage та /face-models/all проходять через той самий /api.

ВАРІАНТ B: NODE.JS ВІДДАЄ І API, І САЙТ
Знайдіть поточний server/src/index.js. Для цієї версії коду він шукає frontend
за шляхом ../../dist від папки server/src/.
Очікувана структура:
  <корінь проєкту>/server/src/index.js
  <корінь проєкту>/server/src/routes/...
  <корінь проєкту>/server/src/utils/...
  <корінь проєкту>/dist/index.html
  <корінь проєкту>/dist/assets/...
Розпакуйте 02_backend.zip у <корінь проєкту>/server/.
Розпакуйте 03_frontend.zip у <корінь проєкту>/dist/.
Назва папки проєкту на хості може бути іншою: орієнтуйтеся на існуючий startup file.

ПІСЛЯ ЗАВАНТАЖЕННЯ
- Відкрийте сайт та перемкніть UA / EN. Українська є початковою для нового відвідувача;
  попередній ручний вибір мови зберігається.
- В адмінці «Правила» й «Банк питань» заповніть поля EN, збережіть і перевідкрийте запис.
- В адмінці FAQ заповніть EN для категорії, питання й відповіді; приховані FAQ теж доступні.
- У «Медіа» заповніть англійську назву відео.
- У новій вкладці «Моделі облич» заповніть англійський підпис. Початкову назву не змінюйте.
- На сайті виберіть EN: перекладений текст має показатися англійською; незаповнений — українською.
- Мова тесту фіксується при його старті й відображається в зданій спробі в адмінці.

КОНФІГУРАЦІЯ ТА МЕЖІ ПЕРЕВІРКИ
Frontend зібрано з адресою API /api на тому самому домені. Частина сторінок також
звертається до /api безпосередньо. Збережіть наявне проксування, не направляйте
запити /api на index.html і не змінюйте діючу конфігурацію хостингу з цього пакета.
Поточні .env та змінні Node.js (DB_*, JWT_SECRET, STEAM_API_KEY, FRONTEND_URL)
залишаються на хості. Архів їх не змінює й не містить.
Необов'язкові VITE_GOOGLE_SHEETS_WEBHOOK_URL та VITE_DISCORD_WEBHOOK_URL
у поточному локальному оточенні не задані; відповідні повідомлення ця збірка
не надсилатиме. Якщо ви користуєтеся ними, потрібна окрема збірка з цими значеннями.
Локально перевірено TypeScript, ESLint (0 помилок, 9 попереджень), збірку,
12 сценаріїв API із підміненою базою та 6 сценаріїв локалізації інтерфейсу.
Для інтерфейсу перевірено повноту словника, параметри повідомлень, основну мову,
збереження вибору мови, незмінність значень персонажа й рендер головної та діалогів
українською й англійською. Перевірки не керують браузером.
Загальний SQL виконано на тимчасовій локальній MariaDB 11.8.9: 14 сценаріїв.
Перевірені збереження рядків, початкових визначень колонок, індексів, зовнішніх
ключів і JSON-перевірок; повторний запуск, старі переклади, помилки структури,
блокування, відновлення таймауту та відмова під час відкритої транзакції.
Дані тестові, структуру взято з надісланого дампа; до робочого сервера не підключалися.
На хостинг з цього комп'ютера нічого не завантажено, робочу базу не змінено.
